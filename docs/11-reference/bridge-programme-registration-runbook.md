# 1. Purpose

This runbook defines the operational procedure for registering learners
into Bridge Programmes within Agile AI University.

The workflow governs:

- eligibility verification
- programme registration
- payment verification
- enrollment
- entitlement creation
- learning resource access
- learner dashboard updates

The objective is to provide a secure, auditable and consistent
registration experience while supporting the University's revenue
operations.

---

# 2. Scope

This runbook applies to:

- AOP → AIPA Bridge
- Future Bridge Programmes
- Alumni upgrade journeys
- Special migration programmes

This document does not apply to:

- Standard programme admissions
- Enterprise bulk enrollments
- Internal staff training

---

# 3. Business Objectives

Bridge Programme registration enables learners to:

- Upgrade existing qualifications
- Continue their learning journey
- Access new licensed learning resources
- Receive new credentials upon successful completion

For Agile AI University this workflow is the primary revenue generation
mechanism for alumni.

# 5. Registration Principles

Every registration follows these principles.

✓ Identity First

✓ Eligibility Before Payment

✓ Payment Before Enrollment

✓ Enrollment Before Resource Access

✓ Complete Audit Trail

---

# 6. Prerequisites

Before registration:

✓ Learner authenticated

✓ Permanent learner_uid available

✓ Existing credential verified

✓ Bridge programme active

✓ Registration window open

---

# 7. Step 1 – Learner Authentication

Learner signs in.

Platform performs:

- Authentication
- Authorization
- Identity Resolution

Result:

Permanent learner identity established.

---

# 8. Step 2 – Eligibility Verification

The platform verifies:

- Existing credential
- Programme completed
- Bridge rules satisfied
- Registration status
- Duplicate registration check

If eligibility fails, registration is blocked.

---

# 9. Step 3 – Display Available Bridge Programmes

Eligible learners are shown available Bridge Programmes.

Information displayed:

- Programme Name
- Duration
- Learning Outcomes
- Fee
- GST
- Registration Deadline

---

# 10. Step 4 – Registration

Learner confirms registration.

Platform creates:

- Registration Record
- Registration Timestamp
- Initial Status

Initial status:

```text
Pending Payment
```

---

# 11. Step 5 – Payment

Learner completes payment through the approved payment gateway.

Information recorded:

- Amount
- GST
- Gateway Reference
- Transaction ID
- Timestamp

---

# 12. Step 6 – Payment Verification

Platform verifies:

✓ Successful payment

✓ Gateway confirmation

✓ Duplicate payment prevention

✓ Amount verification

Only verified payments continue.

---

# 13. Step 7 – Enrollment

Successful payment triggers enrollment.

Platform:

- Creates enrollment
- Links learner_uid
- Associates programme
- Updates learner status

---

# 14. Step 8 – Entitlement Creation

Platform grants access to:

- Bridge Programme
- Learning Resources
- Future assessments
- Programme dashboard

Entitlements are generated by the service layer.

---

# 15. Step 9 – Dashboard Update

Learner dashboard displays:

- Active Programme
- Progress
- Learning Resources
- Schedule
- Completion Status

---

# 17. Administrative Responsibilities

Administrators are responsible for:

- Opening registrations
- Closing registrations
- Monitoring payments
- Resolving exceptions
- Verifying enrollments
- Supporting learners

---

# 18. Payment Exceptions

Possible issues:

- Failed payment
- Duplicate payment
- Gateway timeout
- Manual verification required

Each exception must be investigated before enrollment.

---

# 19. Learning Resource Release

After successful enrollment:

Platform determines:

- Immediate access
- Scheduled release
- Module-based release

Business rules remain within the service layer.

---

# 20. Completion

Upon programme completion:

Platform may:

- Issue new credential
- Generate digital badge
- Update learner profile
- Enable next upgrade pathway

---

# 21. Audit Requirements

Every registration records:

- learner_uid
- Credential ID
- Programme
- Registration ID
- Payment Reference
- Enrollment Timestamp
- Administrator (where applicable)

Audit history is permanent.

---

# 22. Security Requirements

Registration requires:

- Authentication
- Authorization
- Eligibility validation
- Payment verification
- Service-layer enforcement
- Firestore Rules
- Storage Rules

The UI never grants enrollment directly.

# 24. Troubleshooting Matrix

| Issue | Possible Cause | Resolution |
|--------|----------------|------------|
| Registration unavailable | Learner not eligible | Verify prerequisite credentials |
| Payment failed | Gateway issue | Retry or verify gateway logs |
| Enrollment missing | Payment not verified | Confirm transaction status |
| Resources not visible | Entitlements not created | Re-run entitlement resolution |
| Duplicate registration | Existing active registration | Review learner history |

---

# 25. Governance Rules

The following rules are mandatory.

✓ Eligibility before payment.

✓ Payment before enrollment.

✓ Enrollment before learning resource access.

✓ One active enrollment per learner per programme.

✓ All registration actions are audited.

✓ Business rules remain in the service layer.
